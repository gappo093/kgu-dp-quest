## 2. 世界観・題材（改訂）

### 2.1 舞台

架空の都市「**臨海市**」を舞台とする。特定の構造物（橋）ではなく、**都市そのものを
物語の主人公**とする（CLAUDE.md「世界観の基本原則」を参照）。

### 2.2 扱うインフラ分野

以下の分野から、各ミッションの学習目的に最も適したものを選ぶ。全体を通じて
特定の1分野（橋梁等）だけに偏らないこと。

- 橋梁
- 道路
- 河川
- 地盤・斜面
- 都市（市街地・住宅地）
- 避難施設

### 2.3 テーマの軸

防災を軸とした一般土木。地震・豪雨・土砂災害・老朽化など、複数の災害・課題を
織り交ぜてよい（ただし1つのプレイスルー内での一貫性は保つこと）。

### 2.4 v0.1からの継承（変更しない部分）

- Know→See→Think→Actの一本道の流れ（3章の学習設計原則）
- 各ステージ内部の構造（KNOW＝択一クイズ、SEE＝2ラウンド判断＋NPCの声、
  THINK＝仮説→情報収集→再判断、ACT＝NPC分岐による疑似協働）
- STAGE4の「フェーズA・Bは全選択肢が必須NPCへの相談に収束、フェーズCは
  任意NPC相談」という骨格構造
- state.jsのスキーマ設計思想（ステージ内部進捗は非永続、selfAssessmentのみ永続）

## 3. Reflect（振り返る）の追加

### 3.1 位置づけ

大学公式DP図に基づき、ReflectはKnow/See/Think/Actと並ぶ「5つ目のDP」ではなく、
**4つの力を振り返り、統合する中心的プロセス**として扱う（CLAUDE.md参照）。

### 3.2 画面フロー（Phase 6の拡張）

```
バッジ4つ表示・QUEST COMPLETE!
  ↓
【新設】Reflect画面：
  「4つのMissionをクリアしました。でも、ここで終わりではありません。
   あなたはMissionを通して、どんな力を使ったと思いますか？」
  → 選択式または自由記述で、学生自身に言語化させる
  → 正誤は問わない（SEE/ACTと同様、中立な受け止め方をする）
  ↓
開示文：「実は、あなたが体験したこの4つの力が、
  関東学院大学のDiploma Policy（DP）です」
  ↓
対応表（Know/See/Think/Act → DP①〜④）
```

### 3.3 実装方針

Reflect画面の入力（選択式か自由記述か）は、Claude Codeが実装案を2〜3個提示し、
着手前に確認を取ること（CLAUDE.mdの「不明瞭な教育的判断は事前に選択肢を提示する」
というルールに該当する）。

## 5. 学年別のMission設計

### 5.1 基本方針

臨海市という共通世界、画面構造、NPC、ストーリーの骨格は学年間で共通化し、
**学年によって求める判断の深さを変える**。Mission本数を学年ごとに増やす
（16本作る）のではなく、同じMissionの中で分岐・深さを変える設計とする。

### 5.2 学年ごとの位置づけ（目安）

| 学年 | 位置づけ | 求めるレベル |
|---|---|---|
| 1年 | 土木・都市防災を知り始める | 基礎知識、気づく、複数の立場があることを知る |
| 2年 | 専門基礎を使い始める | 情報を読み、理由をもって比較する |
| 3年 | 専門知識を統合する | 複数条件・トレードオフから判断する |
| 4年 | 卒業後を意識する | 制約下で判断し、説明し、他者と協働する |

### 5.3 実装の考え方

- 学年選択はTOP画面またはその直後に移動する（現状YOUR NEXT QUESTのみで
  学年を聞いている構成から変更になる）
- 各ステージのシナリオ本体（舞台・登場人物・大枠の問い）は学年間で共通とし、
  問いの粒度・提示する情報量・フィードバック文の深さを学年に応じて変える
- **重要**：入力形式は全学年で選択式のまま統一する。KNOW（正誤あり）、
  SEE/THINK/ACT（正誤なし、選択→視点提示／NPC対話→再選択という往復構造）
  という各ステージの基本構造は学年に関わらず維持し、学年が上がっても
  自由記述への変更は行わない。自由記述による内省は、Reflect（4ミッション
  終了後、任意入力）のみで扱う
- v0.2では「学年による違いが体験できる」水準までとし、問題バンクの充実は
  v0.3以降に持ち越してよい
- 学年を選ばない利用者（オープンキャンパス参加者等、2章の副対象）には、
  中間的な難易度（3年相当を想定）をデフォルトとして表示する

## 6. Pre/Post DP理解度アンケート

### 6.1 位置づけ

```
学年選択 → Pre → Mission 1〜4 → Reflect → DP開示 → Post → MY DP STATUS
```

### 6.2 設問設計（4段階）

1. **認知**：「ディプロマ・ポリシー（DP）という言葉を知っていますか？」
2. **理解**：「DPとは何を示すものだと思いますか？」（自由記述または選択式）
3. **適用**：「複数の立場から社会課題を考えることは、Know/See/Think/Actの
   どれと最も関係すると思いますか？」
4. **自己認識**：「自分が大学で何の力を身につけようとしているか、説明できますか？」

Postでは同じ4問を再度提示し、Pre/Postでの変化を学生自身が確認できるようにする
（結果は学生本人にのみ表示し、外部への送信は行わない）。

**[改訂] 3番「適用」設問は、他3問（自己申告）と性質が異なる客観的な知識確認と
位置づける。**

- Preでは、これまで通り正誤を表示しない
- Postでは、正誤を表示する。「4つのミッションを終えた後も理解が
  曖昧なままでは、正しい理解につながらない」という考えに基づく
- 対象DPは1問をランダムに選ぶのではなく、**Know/See/Think/Actの4つ
  それぞれについて1問ずつ、計4問を全員に出題する**。ランダムに1問だけ
  出すと、たまたま易しいDPに当たった学生と難しいDPに当たった学生とで
  測定結果にばらつきが生じ、学科として理解度を測定する目的
  （17章、CLAUDE.md参照）に合わないため。学年による出し分けもしない
  （全学年・毎回同じ4問で統一する）

**[改訂] 適用4問の設問文（確定）**

初期案は、Seeの設問だけ「社会課題」という言葉が明示され、Know/Think/Actの
設問にはこの言葉がなく、4問の水準がそろっていなかった（Seeだけ突出して
見えることで、正解が推測できてしまうおそれがあった）。以下の通り、
4問とも「社会課題」を共通の主題としつつ、公式定義の動詞部分で書き分けた
表現に統一する。

- **Know**：「知識や技能を使って、社会課題について理解し考えることは、
  Know/See/Think/Actのどれと最も強く関係すると思いますか？」（正解：Know）
- **See**：「社会課題に関わる、多様な立場や背景を踏まえて物事を判断する
  ことは、Know/See/Think/Actのどれと最も強く関係すると思いますか？」
  （正解：See）
- **Think**：「社会課題の解決に向けて、自ら道筋を立て、根拠を示しながら
  説明することは、Know/See/Think/Actのどれと最も強く関係すると思います
  か？」（正解：Think）
- **Act**：「社会課題の解決に向けて、多様な人と協力しながら行動することは、
  Know/See/Think/Actのどれと最も強く関係すると思いますか？」（正解：Act）

### 6.3 データの扱い（重要な制約）

- v0.2では、回答は**localStorageのみ**に保存する
- サーバー、外部API、データベース、Google Sheets等への自動送信は実装しない
- 個人情報・同意・匿名性・研究利用に関する扱いは、実際に学科として集計・
  研究利用する段階で別途検討する（17章、CLAUDE.md参照）

## 11. 実プレイフィードバックを受けた追加修正（v0.2内での改訂）

develop-v0.2の実装後、実際のプレイを通じて判明した問題への対応。今後の
実装・改訂でもこの章の内容を優先すること。

### 11.1 KNOWの評価をスコアベースにする

3問中の正解数に応じてフィードバックを分ける。

- 3問正解 → 達成した（Know バッジ獲得）
- 2問正解 → 「おしい！」（バッジは獲得、励ましの一言を添える）
- 0〜1問正解 → 「達成できませんでした」（再挑戦を促す、バッジは保留）

### 11.2 STAGE4（ACT）フェーズCのクロージング文を、住民相談の有無で分岐する

地域住民への任意相談をしたかどうかで、最低2パターンのクロージング文を
用意する。「一人だけの判断では情報が揃わなかった」という趣旨の文言は、
実際に住民へ相談した場合は矛盾するため、相談済みの場合は別の文言にする。

### 11.3 DPの正式な定義文を明示する

Post調査で「DPとは何を示すものだと思いますか？」と尋ねる以上、
QUEST COMPLETEの対応表の直後に、大学公式DP図冒頭の定義文の趣旨
（学位授与方針としての位置づけ）を紹介する一文を追加する。

### 11.4 独立したエンディング画面を新設する

YOUR NEXT QUESTは「これから何を学ぶか」の案内に専念させ、末尾から
独立の「エンディング画面」へ遷移させる。

- エンディング画面には「ここでDPについて学ぶ体験は終了です」という
  趣旨の、誰が読んでも終了だと分かる明確な文言を表示する
- ボタンは**「はじめから」のみ**とする。「QUESTを振り返る」ボタンは
  設けない（振り返りたい場合は「はじめから」で最初から体験し直す
  想定とする）
- resumeScreen等、state.jsのスキーマへの影響がないことを確認する

### 11.5 学年別深度の実装原則（5.3の補足）

5.3章に既に明記した通り、学年による違いは選択式のまま表現し、
自由記述への変更は行わない。この原則は今後の学年別実装すべてに適用する。

## 12. 実プレイフィードバックを受けた追加修正（第2弾）

### 12.1 MISSION 1（KNOW）を分野別問題バンク化する

橋梁・構造、地盤・土質、防災（洪水・土砂災害・地震）、河川・水理、都市計画の
5分野×2問＝計10問のプールを用意し、プレイのたびに異なる3分野から
重複なく3問をランダム抽出する。現状の3問が「橋梁構造」「河川（防災）」
「橋梁維持管理」に偏っていた問題を解消する。

### 12.2 MISSION 3（THINK）の設計見直し

**STEP3を正誤なしの判断確認に変更する**

斜面の変位は、地盤崩壊・大雨による地下水位変化・センサー異常など、
現場によって複数の要因が同程度にあり得る現実がある。橋の温度膨張の
ケース（気温データで熱膨張と一意に判断できる）のように「一つの正解に
絞り込ませる」設計は、この題材には合わない。STEP3はSEE/ACTと同様、
正誤を付けない判断確認とする。情報カードは、判断の確からしさを
変化させる材料として機能させつつ、複数の可能性が残り得る前提を維持する。

**「他者への説明」ステップを追加する**

仕様書7章のTHINKの学習目的（原因を考え、解決策を導く。さらに、その考えを
他者に説明する）に対し、現状のSTEP1〜3はSTEP3で終わっており「説明する」を
体験できていない。STEP3の後に、選択式（自由記述不可、21.4の原則に従う）の
説明ステップを追加する。「この判断を上司にどう報告しますか？」等の問いに対し、
結論のみ／根拠データを添えて／他の可能性が残ることを添えて、といった
選択肢を用意する。この中に、斜面の変化が今後の災害にどうつながるかという
視点も含める。

### 12.3 FINAL MISSIONのクロージング文を3パターンに拡張する

住民相談の有無（11.2）に加え、選択した回答の内容も踏まえて分岐させる。

1. 通常の分岐（A・B・Dのいずれかを選んだ場合）：11.2で定めた
   「相談した／していない」の2パターンのまま
2. C（「心配させないよう安全だとだけ伝える」）を選んだ場合（相談の
   有無に関わらず）：この選択が実際の災害対応でも起こりうる典型的な
   失敗パターン（危険性が十分に分からない段階で安易な安心情報を伝え、
   後から状況が悪化した際に住民の信頼を大きく損なう）であることを、
   平易な言葉で伝える
3. Cを選び、かつ住民に相談していた場合：2の内容に加え、「住民の声を
   聞いたにも関わらず、その声を活かさない説明を選んだ」という矛盾にも
   触れる

いずれも正誤を断定する書き方（「不正解です」等）は避け、これまでの
SEE/ACTの中立的なトーンを踏襲した上で、選択が持つリスクに気づかせる
内容にする。

### 12.4 DP開示文の表現を修正する

DPは「4つの力そのもの」ではなく、「その力を身につけた学生に学位を
授与するという大学の方針」である。この不正確さを解消するため、
開示文を以下のように修正する。

- 修正前：「実は、あなたが体験したこの4つの力が、関東学院大学の
  Diploma Policy（DP）です」
- 修正後：「実は、あなたが体験したこの4つの力を身につけることが、
  関東学院大学のDiploma Policy（DP）が示す、卒業までに目指す姿です」

### 12.5 DP対応表に公式の詳細定義文を追加する

Know/See/Think/Actそれぞれに、以下の公式定義文（大学公式DP図より）を
対応表に追加する。

- Know：社会のさまざまな事象やその背景を体系的に理解するとともに、
  社会課題を取り巻く人々と対話し相互理解を図るための幅広い教養および
  各学問領域固有の知識と技能を身につけている。
- See：社会課題を取り巻く人々の社会的・文化的背景を理解したうえで、
  自己を複雑な社会、多様な文化の中に位置づけて客体化し、倫理観と
  公平・公正の精神をもって事象を判断する力を身につけている。
- Think：社会課題の解決に向けて、自ら立てた問いを解決するための道筋を
  立て、他者の意見を尊重したうえで、自らの意見を明確に表現する力を
  身につけている。
- Act：社会・地域・組織の一員として、社会課題に誠実に向き合い、多様な
  背景をもった他者を尊重し協働しながら、課題の解決に向けて、主体的に
  働きかける意欲と態度を有する。

### 12.6 公式DP図をゲーム内に表示する

配信用のアセットフォルダ（例：`assets/images/`）にも画像を配置し、
DP開示画面（対応表・定義文の付近）に実際に表示する。適切なalt属性を
付ける（16章のアクセシビリティ要件）。

## 13. SEE・THINKの複数シナリオ化

### 13.1 方針

KNOW（12.1）と同様、SEE（MISSION 2）・THINK（MISSION 3）にも複数の
シナリオを用意し、プレイのたびにランダムに1本を選ぶ。

**測定（Pre/Post、6.2改訂）とは異なり、SEE・THINKは「体験」であるため、
一貫性より多様性を優先する。** ランダム選択は学年に関わらず行い、
学年内で毎回同じシナリオに統一する必要はない。学年による深さの調整
（5章）は、選ばれたシナリオの中で従来通り適用する。

### 13.2 本数

SEE・THINKそれぞれ2〜3本のシナリオを用意する。既存の1本（SEE：避難指示の
判断、THINK：望洋台の斜面変位）に加えて、新規シナリオを追加する形とする。
シナリオ候補は別途検討し、技術的な精度確認を経てから確定する。

### 13.3 実装上の注意

- 各シナリオは、既存の画面構造（SEE：シナリオ提示→Round1→NPCの声→
  Round2→クロージング、THINK：STEP1→STEP2情報カード→STEP3→報告
  ステップ）を共通のテンプレートとして流用し、シナリオごとの文言のみ
  `data/content.js`で差し替える
- STAGE4（ACT）への伏線（青葉橋の老朽化等）に関わるシナリオがある場合は、
  伏線が保たれるよう注意する（例：SEEの新シナリオでSTAGE4と関連する
  地点を扱う場合、矛盾がないか確認する）

### 13.4 新規シナリオ案（確定）

既存シナリオ（SEE：避難指示のタイミング判断、THINK：望洋台の斜面変位）に
加え、以下4本を追加する。

**SEE-B：避難所運営の判断**

地震後、収容人数に限りのある避難所に、体調の悪い高齢者・小さな子ども連れの
家族・ペット同伴の住民・日本語が不自由な外国人住民が同時に来た場面。
「誰を優先するか」ではなく「限られた空間・物資をどう配分するか」を問う。
既存のSEEと同様、選択→NPCの声→再選択という往復構造を踏襲する。

**SEE-C：ハザードマップ改定と土地利用の対立**

臨海市が最新の調査に基づきハザードマップを改定し、ある住宅地が新たに
浸水想定区域に入った場面。住民から「資産価値が下がる」「今さら言われても
困る」という声が上がる中、住民説明会での対応を問う。ハザードマップは
予測であり保証ではないという技術的な性質と、住民の不安・経済的影響という
社会的な側面の両方を扱う。

**THINK-B：河川水位の急上昇**

臨海川の水位計が「1時間で50cm上昇」というデータを検知。原因候補は
A.局地的な豪雨／B.上流ダムの放流／C.水位計の異常／D.その他。追加情報
（上流域の降水量データ、ダムの放流記録、過去の水位変動パターン、水位計の
点検記録）を提示し、既存THINKと同様、一つに断定させず複数の可能性を
残す設計とする。世界観への追加要素として「臨海川上流のダム」を新設する。

**THINK-C：市街地の道路陥没**

市街地の道路に突然の陥没が発生。原因候補はA.地下埋設管の老朽化／
B.液状化／C.過去の埋設工事の施工不良／D.その他。追加情報（地下埋設物
台帳、周辺の地盤調査記録、過去の陥没履歴、近隣工事の記録）を提示する。

## 14. 「あなたの振り返り」画面の表示方式（改訂）

### 14.1 現状の課題

Pre/Post計7問（認知・理解・適用×4・自己認識）の結果を一覧で一括表示すると、
不正解だった問題がどれで何が正しいのかが埋もれ、DP理解の定着という目的に
対して効果が薄い。

### 14.2 改訂方針

7問を性質に応じて2グループに分け、**1問ずつ順に表示する**（次へボタンで
進む形式。既存のTHINK STEP等と同様のページング形式を踏襲する）。

- **Q1（認知）・Q7（自己認識）**：自己申告のため正誤はつけない。Preでの
  回答とPostでの回答を並べて表示し、変化を本人が確認できるようにする
- **Q2（理解）**：自己申告のため正誤（不正解表示）はつけないが、
  Pre・Postの本人の回答を表示した後に、**参考として「大学が示している
  答え」を提示する**。この文章は、QUEST COMPLETE画面で既に表示している
  大学公式DP図の定義文（spec 12.4・12.5参照）をそのまま再掲する。
  正誤判定ではなく「あなたの考えと、大学の公式な位置づけを見比べてみま
  しょう」という参考情報として位置づける
- **Q3〜Q6（適用：Know/See/Think/Actそれぞれ1問）**：客観的な知識確認と
  位置づけ、正誤を表示する。不正解の場合は視覚的に分かる形（オレンジ等、
  16章の色覚多様性配慮によりテキストラベルも併記すること）で示し、
  正解を併記する

### 14.3 表示順序

Q1→Q2→Q3→Q4→Q5→Q6→Q7の順、または適用4問（Q3〜Q6）をまとめた後に
自己申告3問を見せる順（Q1→Q2→Q7→Q3→Q4→Q5→Q6等）のどちらでも構わない。
実装時に自然な流れを提案すること。
